\section{Resume executif}

ChabahRoot v1.0.0 est une plateforme de télémétrie noyau en temps réel pour la surveillance de sécurité Linux. Le projet est maintenant en production avec une architecture à 4 services clairement séparés:

\begin{itemize}[leftmargin=*]
  \item \textbf{M1 — Ingestion Noyau}: Capture d'événements via eBPF (Auteur: MOUSAAB EL HARMALI)
  \item \textbf{M2 — Moteur de Règles}: Détection de menaces et génération d'alertes (Équipe Cyber)
  \item \textbf{M3 — Normalisateur d'Événements}: Transport et enrichissement des événements (Équipe Cyber)
  \item \textbf{M4 — Orchestrateur de Pipeline}: Coordination et tests d'intégration (Équipe Cyber)
\end{itemize}

La nouvelle structure de production repose sur trois principes:

\begin{itemize}[leftmargin=*]
  \item chaque service a une responsabilité unique et clairement définie;
  \item les frontières entre services sont explicites et bien testées;
  \item tout code mort et dupliqué a été supprimé pour la clarté production.
\end{itemize}

\section{Probleme initial}

Avant la reorganisation, plusieurs problemes de lisibilite etaient presents:

\begin{itemize}[leftmargin=*]
  \item le dossier \texttt{detection/} concentrait des scripts appartenant en realite a plusieurs couches differentes;
  \item la repartition des membres etait visible dans la documentation, mais pas dans l arborescence du code;
  \item les responsabilites M2, M3 et M4 etaient melangees dans un meme espace physique;
  \item la source canonique et les wrappers n etaient pas distingues;
  \item il etait difficile de comprendre rapidement qui possede quelle tache.
\end{itemize}

\section{Principe de reorganisation}

La reorganisation suit le document projet v1.1 (Mai 2026): chaque membre possede une tache, et chaque tache correspond a un service clairement demarque. Le code mort et redondant a ete supprime pour maintenir une base de code production claire et maintenable.

\subsection{M1 — Ingestion Noyau}

\textbf{Auteur:} MOUSAAB EL HARMALI

\textbf{Tache:} ingestion noyau via eBPF.

\textbf{Responsabilite:}
\begin{itemize}[leftmargin=*]
  \item capter les evenements noyau via tracepoints syscall;
  \item compiler et charger les programmes eBPF;
  \item verifier les prerequis systeme (bpftool, clang, llvm-strip);
  \item produire un flux brut via ring buffer (256 KB, <1ms latence).
\end{itemize}

\textbf{Implementation production:}
\begin{itemize}[leftmargin=*]
  \item \texttt{chabahroot/kernel-ingestion/orchestrator.sh} — point d entree principal
  \item \texttt{chabahroot/kernel-ingestion/integration.sh} — gestion eBPF
  \item \texttt{chabahroot/kernel-ingestion/check.sh} — validation prerequis
  \item \texttt{chabahroot/kernel-ingestion/ebpf/event\_capture.c} — programmes noyau
\end{itemize}

\subsection{M2 — Moteur de Regles}

\textbf{Equipe:} Équipe Cyber

\textbf{Tache:} detection de menaces.

\textbf{Responsabilite:}
\begin{itemize}[leftmargin=*]
  \item appliquer 7 regles de detection production;
  \item produire des alertes avec niveaux de severite;
  \item evaluer les conditions via jq;
  \item gerer l audit offensif et la surveillance defensive.
\end{itemize}

\textbf{Implementation production:}
\begin{itemize}[leftmargin=*]
  \item \texttt{chabahroot/rules-engine/rules\_engine.sh} — moteur principal
  \item \texttt{chabahroot/rules-engine/detection\_rules.json} — 7 regles JSON
  \item \texttt{chabahroot/rules-engine/offensive\_audit.sh} — audit offensif
  \item \texttt{chabahroot/rules-engine/defensive\_monitor.sh} — surveillance defensive
\end{itemize}

\subsection{M3 — Normalisateur d Evenements}

\textbf{Equipe:} Équipe Cyber

\textbf{Tache:} transport et normalisation.

\textbf{Responsabilite:}
\begin{itemize}[leftmargin=*]
  \item lire le ring buffer noyau en continu;
  \item decoder les evenements bruts (hex vers JSON);
  \item normaliser en schema JSON standardise;
  \item enrichir avec contexte processus parent;
  \item filtrer les donnees sensibles (password, token, secret, key).
\end{itemize}

\textbf{Implementation production:}
\begin{itemize}[leftmargin=*]
  \item \texttt{chabahroot/event-normalizer/ringbuf\_reader.sh} — lecteur et normalisateur
\end{itemize}

\subsection{M4 — Orchestrateur de Pipeline}

\textbf{Equipe:} Équipe Cyber

\textbf{Tache:} integration et verification.

\textbf{Responsabilite:}
\begin{itemize}[leftmargin=*]
  \item orchestrer les services M1, M2 et M3;
  \item gerer la communication FIFO entre services;
  \item fournir le mode execution production;
  \item valider l integration via suite de tests;
  \item monitorer la sante du pipeline.
\end{itemize}

\textbf{Implementation production:}
\begin{itemize}[leftmargin=*]
  \item \texttt{chabahroot/pipeline-orchestrator/orchestrator.sh} — orchestrateur principal
  \item \texttt{chabahroot/pipeline-orchestrator/integration\_tests.sh} — suite de tests
  \item \texttt{chabahroot/pipeline-orchestrator/run\_detection.sh} — lanceur detection
\end{itemize}

\section{Separation des responsabilites}

\subsection{Ressources partagees}

Le dossier \texttt{chabahroot/shared/} contient seulement les artefacts transverses:

\begin{itemize}[leftmargin=*]
  \item \texttt{logger.sh} — journalisation centralisee avec niveaux DEBUG, INFO, WARN, ALERT
  \item \texttt{rules.conf} — configuration unifiee
  \item \texttt{logs/} — repertoire de journaux
  \item \texttt{tmp/} — repertoire d etat temporaire
\end{itemize}

Il ne contient aucune logique metier de detection, transport ou orchestration.

\subsection{M2 — Moteur de regles}

Le service M2 consomme un flux normalise en JSON. Il ne sait pas comment les evenements sont captures dans le noyau. Ses regles sont composables via conditions jq et stockees en JSON.

\subsection{M3 — Transport et normalisation}

Le service M3 transforme les donnees brutes en schema normalise. Il ne decide pas qu un evenement est malveillant. Sa responsabilite est exclusivement le transport, le decodage et l enrichissement.

\subsection{M4 — Orchestration}

Le service M4 ne reimplemente pas les regles M2 ni la normalisation M3. Son role est strictement l orchestration, la coordination FIFO et la verification d integration.

\section{Verification et execution}

\begin{lstlisting}[style=bashstyle]

\end{lstlisting}

Valide: root, bpftool, clang, llvm-strip, tracefs.

\subsection{Mode production — Pipeline complet}

\begin{lstlisting}[style=bashstyle]
sudo ./chabahroot/pipeline-orchestrator/orchestrator.sh run
\end{lstlisting}

Demarre: M1 → M3 → M2 avec communication FIFO et monitoring.

\subsection{Mode test — Validation integration}

\begin{lstlisting}[style=bashstyle]
sudo ./chabahroot/pipeline-orchestrator/orchestrator.sh test
\end{lstlisting}

Ou directement:

\begin{lstlisting}[style=bashstyle]
sudo ./chabahroot/pipeline-orchestrator/integration_tests.sh
\end{lstlisting}

Suite de tests complete: compilation eBPF, validation regles, normalisation, integration pipeline.

\subsection{Etat du pipeline}

\begin{lstlisting}[style=bashstyle]
sudo ./chabahroot/pipeline-orchestrator/orchestrator.sh status

Affiche: sante M1, M2, M3, logs temps reel.
