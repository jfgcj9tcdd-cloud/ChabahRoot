# ChabahRoot

Pour utiliser ChabahRoot sur une machine Linux, il faut d’abord disposer de `tracefs` sous `/sys/kernel/tracing` ainsi que des outils `bash`, `jq`, `timeout`, `ps` et `find`. Les opérations qui activent les tracepoints du noyau demandent les privilèges root, alors que les essais sur corpus peuvent être lancés sans toucher à la capture système. Le premier contrôle à effectuer est `bash chabahroot/veille_kernel/check.sh`. Cette commande confirme que le point de montage attendu existe et rappelle immédiatement l’exigence de privilèges lorsqu’elle n’est pas satisfaite.

Lorsque la machine est prête, la capture noyau se lance avec `bash chabahroot/veille_kernel/orchestrator.sh start`. Ce processus active les tracepoints suivis par le projet et dépose le flux brut dans le relais utilisé par les autres modules. L’état de cette couche peut être consulté avec `bash chabahroot/veille_kernel/orchestrator.sh status`, puis arrêté proprement avec `bash chabahroot/veille_kernel/orchestrator.sh stop`. Si l’on souhaite simplement activer ou désactiver la couche `tracefs` sans démarrer l’orchestrateur complet, `bash chabahroot/veille_kernel/init.sh` et `bash chabahroot/veille_kernel/cleanup.sh` restent disponibles.

Pour valider le pipeline sans dépendre d’une capture réelle, le chemin le plus simple consiste à lancer `bash chabahroot/chambre_d_analyse/run_detection.sh --sample --pipeline-only`. Cette commande lit le corpus d’exemple, normalise les événements dans `chaines_d_ecoute`, puis applique les règles de `vigie_comportementale`. Si un flux arrive déjà sur l’entrée standard, le même point d’entrée accepte `--stdin`. Si les événements se trouvent dans un fichier, il suffit d’utiliser `--input <fichier>`. Dans les trois cas, l’objectif reste le même : vérifier que la chaîne de transformation et de détection réagit correctement à la source fournie.

Le moteur de règles peut aussi être exercé de manière plus ciblée. `bash chabahroot/chaines_d_ecoute/ringbuf_reader.sh --sample` permet d’observer uniquement la normalisation, tandis que `bash chabahroot/chaines_d_ecoute/ringbuf_reader.sh --sample 2>/dev/null | timeout 2 bash chabahroot/vigie_comportementale/rules_engine.sh` force un passage complet entre la normalisation et l’alerte. Pour un contrôle rapide de l’ensemble des scripts maintenus, `bash chabahroot/chambre_d_analyse/integration_tests.sh` vérifie à la fois la syntaxe shell et la traversée minimale du pipeline d’exemple.
